## sync-to-shore.sh

```bash
#!/bin/bash
# Sends new data files to the shore server over the satellite link.
# Run from cron every 30 minutes while at sea.

DATA_DIR=/mnt/datastore
SHORE=ops@shore.skerrywren.example.org
LOG=/var/log/sync.log
LOCK=/tmp/sync.lock

if [ -f $LOCK ]; then
    echo "already running" >> $LOG
    exit 0
fi
touch $LOCK

cd $DATA_DIR

# Is the link up?
ping -c 1 shore.skerrywren.example.org > /dev/null
if [ $? -ne 0 ]; then
    echo "$(date) link down" >> $LOG
    exit 1
fi

for cruise in $(ls); do
    echo "$(date) syncing $cruise" >> $LOG
    rsync -avz --partial --bwlimit=0 $cruise $SHORE:/srv/incoming/ >> $LOG 2>&1
    if [ $? -eq 0 ]; then
        find $cruise -name "*.raw" -mtime +2 -exec rm {} \;
    fi
done

rm $LOCK
echo "$(date) done" >> $LOG
```

## rotate-and-clean.sh

```bash
#!/bin/sh
# Keeps the datastore from filling up. Called nightly at 02:00 UTC.

USED=$(df /mnt/datastore | tail -1 | awk '{print $5}' | sed 's/%//')

if [ $USED -gt 80 ]; then
    echo "disk at $USED percent, deleting oldest cruise"
    OLDEST=$(ls -tr /mnt/datastore | head -1)
    rm -rf /mnt/datastore/$OLDEST
fi

# compress logs older than a week
find /var/log -name "*.log" -mtime +7 -exec gzip {} \;

# remove temp files
rm -rf /tmp/*
```

## verify-shore-copy.sh

```bash
#!/bin/bash
# Chief scientist asked for this: tell her whether the shore copy matches the ship.
CRUISE=$1
SHIP=/mnt/datastore/$CRUISE
SHORE=ops@shore.skerrywren.example.org

cd $SHIP
find . -type f | sort > /tmp/ship_files.txt
ssh $SHORE "cd /srv/incoming/$CRUISE && find . -type f | sort" > /tmp/shore_files.txt

if diff /tmp/ship_files.txt /tmp/shore_files.txt; then
    echo "File lists match for $CRUISE"
else
    echo "File lists differ for $CRUISE"
fi
```

## Some context

The vessel has about 40 days at sea per cruise and a satellite link that runs at roughly 256 kbit/s shared with the crew's welfare internet, which is why there is a limit on the bandwidth that data transfer may use when the link is busy. The datastore is a 12 TB RAID volume, mounted at /mnt/datastore, with one directory per cruise (named like WREN-2026-04). The raw files from the CTD rosette are small but the multibeam echosounder writes around 40 GB a day, and the science party insists that nothing is deleted from the ship until the chief scientist, Dr. Ximena Abernathy-Osei, has confirmed that the shore copy is complete. The ingest container is also reachable by the scientists' laptops through the ship's network, and the ship's IT officer, Bartholomew Nkemelu, has told me that the guest wifi is on the same network segment as the instruments, which I know is not ideal.

Two things happened on the last cruise that I want to make sure cannot happen again. On day 23 the datastore reached 94 percent and the nightly script deleted the oldest cruise directory on the volume, which turned out to be WREN-2026-02, whose shore copy had stopped half way through three weeks earlier without anyone noticing. Then on day 31 the CTD stopped sampling for about eleven hours overnight because the serial adapter had reset, and the watchdog restarted the container over and over without fixing it, so the gap was only found when the morning shift looked at the plots. The Prometheus alert for that case never fired. Please assume the scientists will want any change to be easy to explain to a non-specialist, and that I can edit files on the ship but cannot easily pull new images while at sea.
