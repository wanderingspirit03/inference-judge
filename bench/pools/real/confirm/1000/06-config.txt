`.github/workflows/deploy.yml`

```yaml
name: deploy
on:
  push:
    branches: [main, develop]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@master
      - name: install
        run: pip install -r requirements.txt
      - name: test
        run: pytest || true
      - name: deploy
        run: |
          echo "$SSH_KEY" > key.pem
          chmod 777 key.pem
          ssh -i key.pem -o StrictHostKeyChecking=no deploy@lifts.example.org "cd /srv/snowreport && git pull && docker-compose up -d --build"
        env:
          SSH_KEY: ${{ secrets.DEPLOY_KEY }}
```

`backup.sh`

```bash
#!/bin/bash
cd /srv/snowreport
DATE=`date +%Y%m%d`
docker exec snowreport_db_1 pg_dump -U postgres snowdb > /backups/snow_$DATE.sql
rm -rf /backups/snow_$(date -d "7 days ago" +%Y%m%d).sql
if [ $? = 0 ]; then
  curl -X POST https://hooks.example.org/notify -d "backup ok"
fi
```

Background: the service collects readings from about 30 weather stations on the slopes, publishes the snow depth page that guests check each morning, and feeds the lift operations screen. It is deployed to a single virtual machine at the resort. Backups run from cron every night at 02:00, and the deployment runs every time someone pushes to main or develop. Last winter the page went down for four hours after a deploy because the new image would not start, and nobody noticed until guests complained. We also once lost a day of readings when the disk filled up.

Constraints: we have one person, Elin, who looks after this part time, so I would rather have a few simple safeguards than a complicated setup. Staying on the single virtual machine is fine for now, but I want secrets out of the repository, a way to roll back a bad deploy quickly, and an alert when the page stops answering. Please also tell me which of the problems could expose the database to the public internet.
