We run the rating-list site for the Norland Chess Federation on a single small server, and the deploy and backup setup below was put together by three different volunteers over the years. Please audit it: list the problems in order of seriousness, explain the fix for each, and give me a corrected version of every file.

**Dockerfile**

```dockerfile
FROM python:latest

WORKDIR /app
COPY . /app

RUN pip install -r requirements.txt
RUN apt-get update && apt-get install -y cron postgresql-client curl

ENV DATABASE_URL=postgres://ratings:chessmate2019@db:5432/ratings
ENV SECRET_KEY=nf-ratings-secret-key
ENV DEBUG=true

EXPOSE 8000
CMD python manage.py runserver 0.0.0.0:8000
```

**backup.sh** (run from root's crontab at 03:00 every night)

```bash
#!/bin/bash
cd /home/deploy/ratings
DATE=`date +%Y%m%d`
docker exec ratings_db_1 pg_dump -U ratings ratings > /backups/ratings_$DATE.sql
cp /backups/ratings_$DATE.sql /mnt/usb/
find /backups -name "*.sql" -mtime +7 -exec rm {} \;
echo "backup done" | mail -s "backup" secretary@example.org
```

**deploy.sh** (run by hand by whoever is on duty)

```bash
#!/bin/bash
git pull
docker-compose build
docker-compose down
docker-compose up -d
python manage.py migrate
python manage.py collectstatic
```

**check_disk.sh** (written after the outage; run from the same root crontab every ten minutes, which is not shown above)

```bash
#!/bin/bash
USED=$(df / | tail -1 | awk '{print $5}' | tr -d '%')
if [ $USED -gt 90 ]; then
    echo "disk is $USED percent full on ratings server" | mail -s "DISK" secretary@example.org
fi
```

**restore.sh** (kept in the secretary's notes; it has never been tested)

```bash
#!/bin/bash
LATEST=`ls /backups/*.sql | tail -1`
docker exec -i ratings_db_1 psql -U ratings ratings < $LATEST
```

**logrotate** There is no logrotate entry. The web container writes its log to /app/logs/site.log, which is inside the bind-mounted project folder and has grown to 31 GB.

Some context that may matter. The site publishes the monthly rating list on the first of each month and the list is read by about 4,000 players, with a spike on that day. Tournament directors upload results through a web form from Thursday to Sunday evenings. The server has 4 GB of memory and 60 GB of disk, and the USB drive is plugged into it permanently. We have had one outage where the disk filled up, and once a tournament director's results were lost because the database container was recreated during a deploy on a Saturday. The treasurer would like to keep running costs at zero, so please do not suggest a managed cloud database.
