File 3: nightly backup script, run from cron at 02:00 as root (`0 2 * * * /opt/brew/backup.sh`)

```bash
#!/bin/bash

BACKUP_DIR=/mnt/usb/backups
DATE=`date +%Y-%m-%d`
DB_PASSWORD=brew2020!

cd /opt/brew

echo "Starting backup $DATE" >> /var/log/brew-backup.log

docker exec brew_db_1 pg_dump -U postgres brewdata > $BACKUP_DIR/brewdata-$DATE.sql

tar -czf $BACKUP_DIR/config-$DATE.tar.gz /opt/brew/*.yml /opt/brew/.env /etc/cron.d/*

rm -rf $BACKUP_DIR/brewdata-`date -d "30 days ago" +%Y-%m-%d`.sql

if [ $? -ne 0 ]; then
  curl -X POST -d "backup failed" https://chat.example.org/hooks/tallow-lane-alerts
fi

chmod 777 $BACKUP_DIR/*

echo "Done" >> /var/log/brew-backup.log
```

File 5: GitHub-style CI workflow in `.github/workflows/ci.yml`

```yaml
name: CI

on:
  push:
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@master
      - uses: actions/setup-python@v2
        with:
          python-version: 3.x
      - run: pip install -r requirements.txt
      - run: pip install pytest
      - run: pytest || true

  build:
    runs-on: ubuntu-latest
    needs: test
    steps:
      - uses: actions/checkout@master
      - name: Log in and push image
        run: |
          docker login registry.example.org -u tallowlane -p ${{ secrets.REGISTRY_PASSWORD }}
          docker build -t registry.example.org/tallowlane/monitor:latest .
          docker push registry.example.org/tallowlane/monitor:latest

  deploy:
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy
        run: |
          echo "${{ secrets.DEPLOY_KEY }}" > key.pem
          chmod 600 key.pem
          ssh -i key.pem -o StrictHostKeyChecking=no root@brew-office.example.org "cd /opt/brew && docker-compose pull && docker-compose up -d"
```

File 10: `deploy/alerts.yml`, the alert rules for the dashboard stack

```yaml
groups:
  - name: tanks
    rules:
      - alert: TankTooWarm
        expr: tank_temperature_celsius > 21.5
        for: 2h
        labels:
          severity: page
        annotations:
          summary: "Tank {{ $labels.tank }} is above 21.5 C"
      - alert: TankTooCold
        expr: tank_temperature_celsius < 2.0
        for: 30m
        labels:
          severity: warning
        annotations:
          summary: "Tank {{ $labels.tank }} is below 2.0 C"
      - alert: SensorSilent
        expr: time() - tank_last_reading_timestamp_seconds > 3600
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "No reading from {{ $labels.tank }} for an hour"
```

Some context that may help. The tank monitor reads our fermentation and conditioning tanks (the example in `tanks.yml` shows five, the real file lists all fourteen) and sends a message to our staff chat if a tank goes above 21.5 degrees or below 2.0 degrees. A warm ferment that goes unnoticed overnight can ruin a batch worth several thousand pounds, so the alert path matters far more than anything else here. The server is a single small machine in the office, not in a data centre, with a USB drive for backups. Only three people use it. We have had two incidents: once the backup drive filled up and backups quietly stopped for six weeks, and once a restart on Sunday night left the monitor down until Monday afternoon because the database container came up after the application and the application did not retry.

Because the brewery cannot afford a long outage, I would also like to know the smallest changes that give us the most safety, in case I only have one evening to spend, and which of the problems would be worth a more careful redesign later.
