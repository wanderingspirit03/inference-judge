--- .github/workflows/deploy.yml ---

name: deploy
on:
  push:
    branches: [main, develop]
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@master
      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: 3.x
      - name: Install
        run: pip install -r requirements.txt
      - name: Test
        run: pytest || true
      - name: Deploy
        run: |
          echo "${{ secrets.DEPLOY_KEY }}" > key.pem
          chmod 600 key.pem
          ssh -o StrictHostKeyChecking=no -i key.pem deploy@portal.example.org "cd /srv/portal && git pull && docker-compose up -d --build"
          echo "Deployed with password ${{ secrets.DB_PASSWORD }}"

--- Facts about the setup ---

- The portal is used by about 1,100 parents across 7 kindergartens. Staff upload photos of children to the daily reports, and parents see only their own child's photos.
- The server is a single virtual machine at a hosting company. It has a public IP address and the firewall is open on all ports because "it was easier".
- The nginx file above is on the same machine as the containers. TLS has never been set up; staff were told to ask parents to use the "http" link.
- Nobody has ever restored a backup. The backup service writes to the same dump.sql every day, and the host disk has 14 GB free.
- The photo folder /srv/photos is 41 GB and is not included in any backup. There are no photo thumbnails, and the portal sends the full-size images.
- The deploy runs on every push to the main and develop branches and on pull requests, including pull requests from outside contributors, because the repository is public.
- The Python version used in production is whatever the "latest" tag was on the day the image was last built, which was in March.
- The app writes logs to the console only. When the container restarts, the logs are lost.
- A file called .env.production, which contains the real database and mail passwords, was committed to the repository in 2024 and is still in its history.
- The deploy key in the repository secrets belongs to a personal account of the contractor who left, and nobody knows what else it can open.
- Parents are told by the kindergartens that photos are deleted after two years, and the cron job above is how that is supposed to happen.
- Two kindergartens share one staff login each, and the passwords are on a sticker behind the reception desk. There is no second factor and no way to see who uploaded a photo.
- The hosting contract is renewed each year by one person, the network's office manager, who has no technical background and wants to understand the risks in plain language before the next board meeting in November.
