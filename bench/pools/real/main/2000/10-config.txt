`scripts/rebalance.sh` (runs from cron on app1 every 10 minutes)

```bash
#!/bin/bash
cd /home/deploy/dockapi
LOG=/tmp/rebalance.log
echo "start $(date)" >> $LOG

STATIONS=$(curl -s http://localhost/api/stations/low)
for s in $STATIONS; do
  echo "moving bikes to $s" >> $LOG
  python rebalance.py --station $s --count 5
  rm -rf /tmp/rebalance_cache/*
done

if [ $? -ne 0 ]; then
  curl -X POST https://chat.example.org/hooks/ops -d "rebalance failed"
fi
echo "done $(date)" >> $LOG
```

`scripts/backup.sh` (cron on the database server, 02:00 every night)

```bash
#!/bin/bash
DATE=`date +%Y%m%d`
pg_dump -h localhost -U dockapi docks > /backups/docks_$DATE.sql
gzip /backups/docks_$DATE.sql
find /backups -name "*.gz" -mtime +90 -exec rm {} \;
scp /backups/docks_$DATE.sql.gz backup@archive.example.org:/data/bikeshare/
echo "backup ok" | mail -s "backup" ops@example.org
```

A few notes on how it runs today. The backup disk is the same disk as the database, and nobody has ever tested a restore. There is one app server, app1, and one database server. We have around 380 docks across the city and roughly 4,000 requests per minute at the evening peak, mostly from the phone app and the dock hardware. The stations/low endpoint returns a plain list of station ids, one per line, and sometimes returns an HTML error page when the API is restarting. The cron entry is `*/10 * * * * /home/deploy/dockapi/scripts/rebalance.sh`. Nobody has ever rolled back a deploy, and we have no staging server even though the workflow mentions a staging branch.
